# Invoice draft HTTP boundary

POST /api/v1/invoices now delegates to atomic source allocation. The strict JSON
request accepts patientId, nonempty unique billableItemIds and optional
appointmentId only. UUID Idempotency-Key is mandatory; actor comes from verified
staff authentication. Duplicate/trailing JSON, unknown fields, supplied amounts
and invalid identities are rejected before writes. Administrator and Assistant
are permitted; normal JWT and live IAM eligibility run before every retry.

The response is the stored 201 invoice representation and relative Location.
Source/owner eligibility and changed-request replays return 409. Persistence or
private owner unavailability returns a safe 503. Unauthenticated/unauthorized
requests remain 401/403. There is no fallback owner state.

Configure BILLING_APPOINTMENTS_ORIGIN, BILLING_APPOINTMENTS_SERVICE_TOKEN_FILE
(absolute path) and, only on explicit development HTTP networks,
BILLING_APPOINTMENTS_LOCAL_DEVELOPMENT. The optional compose.appointments.yml
overlay mounts a separately provisioned credential directory read-only.
Supply the official appointments:encounter-status:read scope with the owner's
issuer/audience. Staff JWTs and Billing-to-IAM credentials are not substitutes.
Provisioning/rotation belongs to platform identity management; no secret value
or production issuer is generated by this feature. Both unset keeps draft
creation closed with 503 while existing reads remain available. Partial or
unsafe configuration prevents startup.

The HTTP tests isolate the boundary with test doubles. PostgreSQL transaction
tests separately verify exact replay, competing allocation and rollback. These
tests alone do not establish live Appointments or browser acceptance.
